## Одним абзацом

**RTLib** — бібліотека процедурної генерації **великих структур** (цитаделі, міста-поселення, лабіринти) з **NBT-тайлів**. Назва кожного NBT-файлу — це **машиночитаний опис** кімнати/сегмента (тип, форма, розмір, входи/виходи, стиль, скільки поверхів займає, глобальний ID). Алгоритм **не малює блоки вручну** — він **підбирає і складає готові тайли**, будує коридори там де треба, підганяє під рельєф (кручі, річки, мости), і дозволяє іншим модам викликати процедури типу «згенеруй цитадель тут».

Філософія: **максимум у конфігах**, мінімум лізти в Java — розробник міняє JSON (decodelists, tilelists), а не код.

## NBT-тайли: назва = специфікація

### Роздільники
- **`_`** — між полями назви
- **`-`** — кілька значень всередині одного поля
- **`:`** — у додаткових виходах (`AdditionalExit1:North`)

### Приклад (застарілий, але зрозумілий)
```
Hall_10x12_East_West_AdditionalExit1:North_3_2_1
```
| Частина | Значення |
|---------|----------|
| Hall | тип кімнати |
| 10x12 | size |
| East / West | entrance / exit |
| AdditionalExit1:North | додатковий вихід |
| 3_2_1 | **Style_floorCount_ID** |

### Поля (узгоджено)
- **Тип кімнати:** `room`, `corridor`, `stairroom`, `grandroom`, `throneroom`
- **Форма:** `circle`, `square`, `hexagon`, `pentagon`, `octagon`, `star:N`, трикутники
- **Трикутники:** `triangle-pria(45;45)` — підтип через `-`, кути в дужках з `;` (перевірено на Windows)
- **Сторони входу/виходу:** N, S, E, W + NE, NW, SE, SW + `none`
- **none:** алгоритм **намається не брати** такий тайл; якщо іншого виходу нема — вставить
- **AdditionalExits:** `AdditionalExit1:North-AdditionalExit2:South`
- **Style** — числовий ID стилю (один на всю структуру при генерації)
- **floorCount** — скільки **фізичних поверхів** займає тайл (сад = 3, сходи = 2)
- **ID** — **глобально унікальний** серед усіх тайлів моду (останнє поле в назві)

### ID і tilelists
- NBT лежать у `data/rtlib/structures/`
- При завантаженні система **сканує файли**, парсить назви, будує **ID → TileData**
- **Tilelists** містять **тільки ID**, не повні назви файлів
- **decodelists/** — JSON-схема: які поля, порядок, special_rules (напр. triangle → наступне поле = кути). **Один файл**, різні інструкції для різних ситуацій. Невідоме поле → warning + ignore

## Цитадель: як збирається

### Порядок
1. Визначити **ключові точки**: вхід/вихід, тронна зала, сходи вгору/вниз
2. Побудувати **ламана лінія** між ними (основний маршрут)
3. **Обабіч ламаної** — кімнати
4. Кімнати **з'єднуються entrance↔exit** напряму (не тільки через коридор)
5. **Коридор** — лише там, де між двома кімнатами **нема прямого збігу** входу/виходу (заповнює gap)
6. Ламана **може перриватись** — гравець іде через кімнати, не тільки коридором

### Коридори
- Можуть бути **NBT-тайл** `corridor`
- Або **алгоритмічно** (підлога + стіни), якщо нема підходящого тайла / є простір між кімнатами

### Головне правило
**Не лишати пустих місць** — простір має бути заповнений кімнатами/коридорами. Кімната може не мати виходу в коридор, але мати виходи в інші кімнати.

## Поверхи цитаделі

### displacement
- **Окремий параметр поверху** (не частина MultiShape, не в назві тайла)
- Передається при виклику з іншого мода
- **2D (X, Z)** у блоках, може бути від'ємним
- **Відносно центру першого поверху** (= центр структури)
- Застосовується **до побудови фігур** — щоб поверхи стикались (вежа збоку, зміщені поверхи)
- Зміщує **весь поверх** включно зі стінами

### MultiShape (кілька фігур на одному поверсі)
- Кожна **підфігура**: форма, position, rotation, `connectToBelow`
- **position:** координати `10,5` або shortcuts `corner`, `center`, `edge` (менш точно, вирівнювання поправить)
- **connectToBelow:** вирівнювання з **такою ж іменованою** підфігурою на поверсі нижче — **пріоритет над координатами**
- **rotation:** і на рівні поверху, і окремо на підфігурі
- Перетин фігур → **внутрішні стіни**

## Фігури

### Стандартні
circle, square, hexagon, pentagon, octagon, star, triangle (+ підтипи)

### Formula
- Будь-яка фігура через **`formula:`** (напр. `formula:x^2 + y^2 <= 400`)
- Стандартний пріоритет операцій, дужки, `+ - * / ^ abs sin cos sqrt max min`
- sin/cos у **градусах**
- Трикутник можна і через formula, і через triangle-pria — для тих хто не хоче формули

### Процедури форм
- **GenerateMazeBoundedSimpleShape** — стандартні фігури
- **GenerateMazeBoundedArbitraryShape** — formula / довільні
- **GenerateMazeUnbounded** — «нескінченний» лабіринт (для вимірів), обмежений лише `max_iter` (не зависнути сервер)

## Міста / мегаструктури (TerrainAdapter)

Місто = тайли **з settlement tilelist** (не кімнатні), кожен сегмент перевіряє **локальну** висоту під собою.

### Скан рельєфу
- Повний **периметр** майбутньої структури
- Знайти **макс. перепад** і напрямок кручі
- **Центр міста** — **впритул до кручі**

### Круча
| Перепад | Поведінка |
|---------|-----------|
| ≤ ~30 блоків (конфіг) | **Сходи** вздовж скелі між дорогами, що мали б бути безперервними (шлях через Bresenham, тайлові сходи) |
| > порогу | **Erebor-режим:** частина структури **фізично йде під скелю** (не просто обрізка — як половина кола в горі) |

Міста **бажано** генерувати там, де **великий перепад висот** — це фіча, не баг.

### Річки
1. Перевірка **біому** річки
2. Потім **блоки води**
3. Якщо води багато (>5 підряд, ширина >6) **без біому** — все одно **river_grate**

### Мости
- Тайли `bridge_start`, `bridge_middle`, `bridge_end` з **settlement tilelist**
- Рівень води = **найвищий блок води** під мостом
- Після вставки — **waterlogging** на блоках що підтримують
- Типи сегментів: NORMAL, BRIDGE, RIVER_GRATE, CLIFF_STAIRS

## Стіни

- **GenerateStructureWall** — стіни **структури** (цитадель/місто)
- **GenerateWall** — **неструктурні** стіни (можуть йти вздовж біому/ландшафту)
- **wallListId** — окремий список тайлів **тільки для стін**

## Виклик з іншого мода

Процедури (приклади з промпту):
- `generateCitadel(...)` — style (один int), perFloorListIds (поверх → ID списку тайлів), specialConfigs, shapeProperties з displacement/rotation/multishape
- Style фільтрує тайли на всю структуру
- Displacement/rotation — **параметри поверху**, не тайла

**Workflow для AI:** перед генерацією кожного файлу — **підтвердження**; якщо щось неясно — **питати**, не вигадувати.
